核心判断

Q2 不是单纯“总工时下降”，而是在 Jira 需求规模持平的情况下，投入重心从设计驱动探索转向 PRD 交付。

PRD 需求数从 259 增至 267，工时从 681.4 天微降至 674.3 天，主交付盘保持稳定。
设计驱动需求工时从 148.9 天降至 102.4 天，是整体工时下降的主要来源。
验收工时占比上升，需要关注 AI coding 后开发实现质量、组件调用和设计验收反复的问题。

AI 提效信号

1

调研效率提升

调研平均工时在总计口径下降 8.8%，设计驱动需求调研平均工时下降 13.1%。AI 对竞品收集、问题归纳、用户反馈整理的帮助更明显。

2

PRD需求类型，设计执行效率改善

PRD 执行平均工时从 2.5 天下降到 2.3 天，下降 8.4%。AI 对设计执行中的资料整理、方案生成、规范检查和表达产出有较明确帮助。

3

验收阶段成为新的质量观察点

PRD 验收平均工时上升 28.3%，总体验收工时也上升 31.0%。这不一定是设计侧效率下降，更可能反映 AI coding 后开发实现质量和组件调用一致性需要更强流程约束。

结论表达

AI 的短期收益更明显体现在“调研提速、PRD 执行提速、交付主盘稳定”，但尚未体现为执行工时占比明显下降。

Q2 Jira 需求数保持不变，PRD 需求数略增，PRD 总投入基本持平。与此同时，调研平均工时下降，PRD 执行平均工时下降，说明 AI 已经帮助设计师在信息收集、内容整理、方案表达和交付执行中节省时间。

需要谨慎说明的是，验收阶段工时上升，可能与 AI coding 后的开发实现质量、组件复用一致性和人工质量把控流程有关。后续如果要进一步放大 AI 提效收益，需要把 AI 应用从设计侧前置环节延伸到研发交付质量协同。

执行阶段进一步提效的解决思路：一是封装 demo 转 Figma 的 Skill，降低从可运行页面到设计资产的转换成本；二是推进 HTML 直接交付，让设计产出更接近可复用、可验证的交付形态。

H2 计划：设计系统与 HTML 交付闭环

下半年计划

下半年计划与研发泽秋共建设计系统，把设计交付从“静态稿”升级为“可运行的 HTML 版本资产”，打通 AI Native 工作流下从参考输入到 HTML 落地的整条链路。

这套系统既支持从线上抓取代码，也支持根据截图还原页面，并在生成阶段就纳入 Skill 与组件库约束，最终沉淀为可回溯、可复用、可持续迭代的 HTML 输出体系。

要解决的问题

让设计输出直接进入交付链路

解决 AI 生成 HTML 场景下还原不稳、组件约束后置、结果难复用的问题，让设计输出更接近研发可接入产物。

要建设的能力

一套可复用的 HTML 生成机制

通过代码抓取、截图还原、Skill 约束和研发共建规则，把页面输出过程标准化，而不是依赖个人经验处理。

最终产出

版本化的设计资产库

每次项目留下可运行 HTML、规则映射和版本记录，后续页面生成直接复用，持续反哺设计系统能力。

系统运作 SOP

运作方式：把“输入参考稿 → 在 Skill 约束下生成 HTML → 设计自验 → 研发验收 → 版本沉淀”做成统一 SOP，让每个项目都走同一条可复用链路。

输入层
1

任务触发与来源识别

任务进入系统后，先判断参考来源，统一进入后续生成流程。

  • 线上页面：直接抓取结构和样式。
  • 截图或视觉稿：走截图拆解与还原。
  • 统一补充页面状态、业务边界和交付说明。
生成层
2

在 Skill 约束下生成高还原 HTML

HTML 生成阶段即纳入 Skill 与组件库规则，确保输出结果既高还原，又能进入正式交付链路。

  • 同步完成页面还原与组件映射。
  • 自动补齐 token、slot、状态和命名规范。
  • 输出组件库约束下的 HTML 交付稿。
验证层
3

设计先完成视觉自验

设计先完成视觉和状态校验，保证提交给研发前已经达到设计交付标准。

  • 核对版式、间距、层级和交互状态。
  • 确认组件映射没有破坏视觉表现。
  • 整理特殊说明和边界条件。
验收层
4

提交 HTML 给研发验收

设计自验通过后，再进入研发验收，确认 HTML 满足接入和维护要求。

  • 校验组件合规性、代码结构和扩展性。
  • 问题回流到设计与 Skill 规则侧修正。
  • 沉淀差异点，作为下一轮优化输入。
沉淀层
5

保存 HTML 版本记录

每次输出都以版本节点保存，形成可回溯、可对比、可复用的设计交付资产库。

  • 保存 HTML、截图对照和关键注释。
  • 记录 Skill 版本、映射规则和异常处理。
  • 支持回退、对比和跨项目复用。

管理价值 1：统一入口

无论来自线上代码还是截图，都会进入同一套 HTML 生成与验收机制，降低流程分叉和协作成本。

管理价值 2：沉淀资产

最终产物不再只是一次性页面，而是可运行、可回溯、可继续复用的 HTML 设计资产，为后续项目持续提效。

能力迭代与版本回溯

长期价值：每次项目都会留下可复用样本，持续驱动 Skill 与组件库升级，让后续页面生成越来越快、越来越稳。

异常样本收集

记录映射不足、还原误差和需要人工修正的场景。

共建规则补齐

与研发共建组件规则、结构约束和生成策略，持续更新 Skill。

新能力发布

将新组件、新模板和新规则投入下一轮生成流程，减少重复劳动。

下一轮复用

后续任务直接复用历史版本和映射经验，形成更稳定的 HTML 输出链路。

版本记录示意

V0 参考输入

线上页面或截图原始输入，作为还原目标。

V1 受约束还原版

在 Skill 与组件库约束下直接生成高还原 HTML。

V2 研发验收版

经设计自验和研发验收后的可交付 HTML 版本。

V3 迭代增强版

补齐新能力后回写设计系统，保留可回溯对照关系。
